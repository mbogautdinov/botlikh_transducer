# Botlikh morphological transducer

A finite-state morphological analyzer and generator for Botlikh (Andic, Nakh-Daghestanian), written in
[lexd](https://github.com/apertium/lexd) and twol and compiled with [HFST](https://hfst.github.io/).

The transducer covers nouns, adjectives, numerals, pronouns, invariable words (adverbs, postpositions, particles,
conjunctions, interjections, onomatopoeia) and clitics, including the enclitic copula. **Verbs are not covered.**

| Module | Lexicon |
|---|---|
| nouns | 6,012 lemmas (dictionaries, names and toponyms of the corpus) |
| adjectives | 1,838 entries |
| invariable words | 1,392 entries |
| numerals | closed class |
| pronouns | closed class (personal, demonstrative, interrogative and other pronouns) |
| clitics | 32 clitics and the copula |

## Requirements

* `lexd`, HFST (`hfst-twolc`, `hfst-lookup` and the other command-line tools), `make`, `bash`. The transducer was built
  with lexd 1.3.1 and HFST 3.16.0. On Debian and Ubuntu:

  ```bash
  sudo apt-get install hfst lexd make
  ```

  If the packages are not found, add the package repository of the Apertium project first:

  ```bash
  wget -q https://apertium.projectjj.com/apt/install-nightly.sh -O install-nightly.sh
  sudo bash install-nightly.sh
  sudo apt-get install hfst lexd make
  ```

* Python 3 for the tests (standard library only). The scripts that build the lexicons and the evaluation notebooks need
  the packages of `requirements.txt`.

## Build

```bash
make
```

`make` compiles three versions of the analyzer. They have the same lexicon and differ in the treatment of clitics:

| File | Clitics |
|---|---|
| `bot_noclitics_analyzer.hfstol` | no clitics are attached to words |
| `bot_allclitics_analyzer.hfstol` | up to three clitics after a word of any part of speech, then (optionally) the copula |
| `bot_analyzer.hfstol` | clitics and the copula after invariable words and pronouns only |

All three versions analyse a clitic that is written as a separate word. The generators (`bot_generator.hfst`,
`bot_noclitics_generator.hfst`, `bot_allclitics_generator.hfst`) are built at the same time. A module can be built
alone, for example `make bot_nouns_analyzer.hfstol`. `make clean` removes the compiled files.

## Usage

An analyzer returns the analysis of a word form (*решиди* is the ergative of *реши* ‘year’):

```bash
$ echo "решиди" | hfst-lookup -q bot_allclitics_analyzer.hfstol
решиди	реши<N>><erg>	0.000000
```

A generator does the opposite and builds a form from its analysis:

```bash
$ echo "реши<N>><pl>" | hfst-lookup -q bot_allclitics_generator.hfst
реши<N>><pl>	реше	0.000000
```

Several words are analysed at once if every word stands on its own line. A phrase can be split with `tr`
(the phrase means ‘300 years ago’ and is taken from the Spoken corpus of Botlikh):

```bash
$ echo "гьабубешунда решиди ссеъахвала" | tr ' ' '\n' | hfst-lookup -q bot_allclitics_analyzer.hfstol
гьабубешунда	гьабубешунуда<NUM>><num>	0.000000

решиди	реши<N>><erg>	0.000000

ссеъахвала	ссеъа<ADV>=<indef>	0.000000
```

A file with one word per line is analysed in the same way:
`hfst-lookup -q bot_allclitics_analyzer.hfstol < words.txt`.

Many forms have more than one analysis; then every analysis is printed on its own line. A form that is not
recognised is returned with `+?`.

### Format of the analysis

An analysis is the lemma, the tag of the part of speech and the tags of the morphemes: `lemma<POS>>tag>tag=clitic`.

* `>` is a boundary between morphemes, `=` is a boundary before a clitic: `килу<N>><apud.lat>`, `ден<PRON><I>=<add>`,
  `ваша<N>=<cop>`.
* A class prefix stands before the lemma: `<m>>бечIер<ADJ>` for вечIер.
* A clitic that is written as a separate word has no lemma: `=<quot>` for талу.
* Parts of speech: `N`, `ADJ`, `NUM`, `PRON`, `ADV`, `POSTP`, `PTCL`, `CONJ`, `INTJ`, `ONOM`.

### Spelling of the input

Forms are written in lower case. The palochka can be written as `I`, `Ӏ`, `ӏ` or `1`; in the analysis it is always the
Latin `I`. A nasalised vowel of the dictionaries (`ᴴ`) can be written as `ᴴ` or `н`. Vowel length and stress are not
written.

## Structure of the repository

```
Makefile                  compiles the transducer
remove_hyphen.twol        removes the hyphen of the lexical side from the surface form
nouns/  adjectives/  numerals/  invariables/
    *_formation.lexd      patterns and affixes, written by hand
    *_lexicon.lexd        the lexicon, generated by scripts/build_*.py (translations after #)
    *.twol                two-level rules, written by hand
    *_manual.tsv, *_closed.tsv        tables written by hand: additions to the dictionaries, closed classes
    *_auto.tsv, *_review.tsv, ...     tables written by the scripts (see below)
invariables/
    clitics_formation.lexd, clitics_lexicon.lexd      clitics
    copula_da.lexd, copula_ida.lexd                   the two variants of the copula
pronouns/
    pronouns.lexd, pronouns_bare.lexd, pronouns.twol  a closed class, written by hand
data/botlikh_dicts.xlsx   the dictionary table (Botlikh entries of the Comparative Andic dictionary database)
scripts/                  the scripts that build the lexicons and the evaluation data
tests/                    test tables and the script that runs them
evaluation/
    corpus/               the words of the corpus with the gold standard and the manual annotation of the analyses
    texts/                texts without glosses
    notebooks/            the notebooks of the evaluation
```

## Lexicons

The lexicons are a part of the repository, so `make` does not need Python. To build them again from the dictionary
table and the tables written by hand:

```bash
pip install -r requirements.txt
make lexicons
```

| Script | What it does |
|---|---|
| `split_by_pos.py` | splits `data/botlikh_dicts.xlsx` into one table per part of speech (`data/pos_dicts/`) |
| `parse_invariables.py` | reads the notation of the dictionary entries of the invariable words (variants, optional segments, class markers) → `invariables/invariables_auto.tsv` |
| `parse_adjectives.py` | finds the position of the class marker and the stem of every adjective → `adjectives/adjectives_auto.tsv` |
| `build_nouns.py` | reads the lemmas, the translations and the plural suffix given in the entry (`мн.`) and writes `nouns/nouns_lexicon.lexd`; the suffix becomes a tag of the entry |
| `build_adjectives.py`, `build_invariables.py`, `build_numerals.py` | write the lexicons of the other modules from the tables |
| `corpus_words.py` | makes the table of the words of the corpus (`evaluation/corpus/botlikh_corpus_words.xlsx`) from the export of the corpus (`botlikh_corpus_merged.xlsx`); the parts of speech and a few corrections of the segmentation and the gloss were then added to the table by hand |
| `make_khabar_texts.py` | collects the texts without glosses into `evaluation/texts/botlikh_khabar.tsv` |

Entries that the scripts could not read safely are not compiled; they are listed in `*_review.tsv`, `*_skipped.tsv`
and `invariables_mwe.tsv` (multiword entries). Words and forms that are not in the dictionaries are added in
`*_manual.tsv`, with the source of every row.

## Tests

```bash
make test
```

or, for one table or for another version of the transducer:

```bash
python3 tests/run_tests.py tests/nouns.tsv
python3 tests/run_tests.py --fst bot_analyzer.hfstol
```

Every table in `tests/` has four columns: `form`, `analysis`, `expected` and `source`. With `expected = yes` the
analysis must be among the analyses of the form (other analyses may be present); with `expected = no` it must not be
among them. The script prints the number of passed tests for every table and lists the tests that failed.

| Table | Tests | Forms |
|---|---|---|
| `nouns.tsv` | 64 | plural and case forms from the grammar sketch of AA2019, the dictionaries and the corpus |
| `adjectives.tsv` | 63 | class and case forms from the grammar sketches of SA2012 and AA2019; nine forms are constructed by analogy |
| `numerals.tsv` | 150 | forms from the dictionaries, the grammar sketches and the corpus |
| `pronouns.tsv` | 200 | forms from the grammar sketch, the dictionaries and the corpus |
| `invariables.tsv` | 106 | words from the grammar sketches and the dictionaries |
| `copula.tsv` | 16 | forms with the copula from the corpus; three forms with the wrong variant of the copula must not be analysed |

The tests are written for `bot_allclitics_analyzer.hfstol` (the default). Most tests of `copula.tsv` fail for the
other two versions, which do not attach the copula to nouns.

## Evaluation

The gold standard is the [Spoken corpus of Botlikh](https://lingconlab.ru/botlikh/): 1,273 Botlikh word tokens
(743 different entries; Russian and Avar words and words with an unclear gloss are excluded). All analyses that the
transducer gives for these words were compared with the glosses of the corpus by hand
(`evaluation/corpus/botlikh_corpus_annotation.xlsx`, column `correct`: 1 = right, 0 = wrong).

| Tokens | Version | Recognised | With a right analysis | Precision | Recall | F1 |
|---|---|---|---|---|---|---|
| all words (1,273) | no clitics | 67.6% | 52.3% | 0.49 | 0.54 | 0.51 |
| | all clitics | 80.0% | 61.5% | 0.39 | 0.63 | 0.48 |
| without verbs (885) | no clitics | 83.5% | 75.3% | 0.55 | 0.76 | 0.64 |
| | all clitics | 95.5% | 88.5% | 0.45 | 0.89 | 0.60 |

On four texts without glosses (`evaluation/texts/botlikh_khabar.tsv`, 3,257 tokens) the version without clitics
recognises 54.3% of the tokens and the version with clitics after all words 66.2%.

The notebooks in `evaluation/notebooks/` reproduce these numbers: they install the tools, build the transducer from
this repository and write all tables and figures.  

The files with the suffix `_with_outputs` are the same notebooks after a run in Google Colab: they show
all tables and figures without running anything.

| Notebook | Content |
|---|---|
| `botlikh_eval_1_corpus_words.ipynb` | analyses of the words of the corpus, coverage, the table for the manual annotation |
| `botlikh_eval_2_texts_clitics.ipynb` | coverage and ambiguity on the texts without glosses, the two treatments of clitics |
| `botlikh_eval_3_annotation_metrics.ipynb` | precision, recall, F1 and accuracy from the manual annotation, per token and per entry, by part of speech |

## Limitations

* Verbs are not analysed. Verb forms that look like forms of other parts of speech can get a wrong analysis.
* Plural forms are built only for the nouns whose dictionary entry gives the plural suffix (1,907 of 6,012 lemmas).
* Multiword entries of the dictionaries are not compiled.
* The analyses are not ranked or disambiguated.
* A part of the corpus was used when the transducer was built: words and forms of the corpus that were not recognised
  were added to the lexicon and to the patterns.

## Data and sources

* **Dictionaries.** `data/botlikh_dicts.xlsx` is the Botlikh part of the *Comparative Andic dictionary database*
  (Moroz et al., 2025, version 0.12, <https://doi.org/10.5281/zenodo.4782876>), which is distributed under the
  Apache License 2.0. The entries come from two dictionaries: Saidova & Abusov (2012), *Ботлихско-русский словарь*
  (SA2012), and Alekseev & Azaev (2019), *Ботлихско-русский словарь* (AA2019). The grammar sketches of the two
  dictionaries and the corpus are the sources of the patterns.
* **Corpus.** Zadykian, S., Naccarato, C., Verhees, S., & Sadakov, I. *Устный корпус ботлихского языка с. Ботлих*.
  Linguistic Convergence Laboratory, HSE University. <https://lingconlab.ru/botlikh/>
* **Texts.** Moroz, G., Naccarato, C., & Verhees, S. (2020). *Буйхалъи ххабарде* [Botlikh stories]. Linguistic
  Convergence Laboratory, HSE University. <https://sverhees.github.io/botlikh_khabar/>
* **Metrics.** Kazakova, T. B., & Moroz, G. A. (2025). *Конечные автоматы в морфологическом анализе 2024/2025*.
  <https://agricolamz.github.io/2025_morphological_transducers/>

The corpus data and the texts belong to their authors and are included here only to make the evaluation
reproducible.
